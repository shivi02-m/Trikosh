                Financial Intelligence Workspace - Codex Build Specification

Build one adaptive financial intelligence platform with three workspace types: Personal, Household, and
Business. The product must go beyond transaction tracking. It should explain financial changes, forecast future
spend, manage budgets and subscriptions, surface AI insights, and provide BI-style analysis with traceable
evidence.

Core product positioning

Most expense trackers show where money went. Ops Mind AI should help users understand why spending changed, what
is coming next, what deserves attention, and what action can be taken.

1. Product Modes

Workspace       Primary Users                 Core Purpose
Personal        Individual / bachelor
Household       Couple / family / dependents  Track income, expenses, budgets, subscriptions, savings goals, salary-cycle spending and
Business        Company / team                personal AI insights.

                                              Manage shared and private spending, members, events, festivals, goals, bills and
                                              household financial intelligence.

                                              Control spend, departments, approvals, policies, vendors, SaaS, budgets, projects, BI and
                                              optional revenue/GTM analytics.

2. Build Principles for Codex

� Treat this document as the master product scope. Implement in phases rather than attempting all features in one change.
� Use a workspace-aware data model from the start. Every financial record must belong to a workspace and obey access
rules.
� Keep AI server-side. AI responses must be grounded in stored workspace data and should expose evidence or linked
source records.
� Forecasts and recommendations must be labeled as estimates; never present them as guaranteed outcomes.
� Separate regular financial behavior from exceptional/event spending so one-off purchases do not distort the baseline.
� All dashboard values, charts and AI summaries must reconcile to underlying source records.
� Business-mode revenue or pipeline analytics must distinguish association from causation.
� Use synthetic demo data only for portfolio/demo workspaces.

3. Suggested Architecture

Layer           Recommendation
Frontend        React + TypeScript; responsive SaaS dashboard; reusable workspace-aware components.
Backend         FastAPI or Node.js API with authorization enforced server-side.
Database        PostgreSQL with workspace_id on all scoped records; normalized dimension tables where useful.
Authentication  Secure email/password or external auth provider; protected sessions; role-aware access.
AI              LLM calls only through backend; retrieval limited to current workspace; structured outputs for classifications/insights.
Charts          Interactive chart library with drill-down and filter propagation.
File Storage    Secure receipt/invoice attachment storage with metadata in database.

4. Core Data Model

Recommended entities: users, workspaces, workspace_members, profiles/preferences, household_members,
departments, transactions, categories, tags, budgets, budget_lines, subscriptions, recurring_rules, events,
savings_goals, upcoming_expenses, vendors, projects/clients/campaigns, expense_submissions, approval_steps,
expense_policies, attachments, notifications, ai_insights, audit_log, import_batches, source_metadata,
revenue_pipeline_records (Business/GTM phase).

Every scoped entity should contain a workspace reference. Keep transaction classification fields structured enough to
support regular vs exceptional, essential vs discretionary, member/team ownership, event/project attribution, recurring rules,
and source/audit metadata.

� Three adaptive workspaces under one architecture.

9. Definition of Done

� Feature behavior matches acceptance criteria in the Excel checklist.
� Authorization is enforced server-side for every workspace-scoped operation.
� Numbers shown in KPI, chart, report and AI narrative reconcile to the same source data.
� AI features fail safely when the data needed to answer is unavailable.
� Forecasts/recommendations are clearly labeled estimates and show their basis.
� Responsive behavior is verified on mobile and desktop.
� Import/export flows handle invalid rows and preserve traceability.
� Synthetic demo workspaces can be reset to a known state.
� No real personal or client financial data is bundled in the repository.

10. Codex Execution Instruction

Do not implement the entire product in one pass. Start from the earliest incomplete P0 feature in the checklist.
For each implementation batch: (1) state which feature IDs are being implemented, (2) inspect existing code
before changing it, (3) preserve the workspace-aware architecture, (4) add/update tests where feasible, (5) run
lint/build/tests, (6) summarize changed files and remaining dependencies, and (7) update checklist status only
after acceptance criteria are met.

Recommended first Codex task: implement CORE-001 through CORE-004 and CORE-010/CORE-011, then EXP-001
through EXP-003. Once those foundations are stable, continue by Phase and Priority from the Excel checklist.
